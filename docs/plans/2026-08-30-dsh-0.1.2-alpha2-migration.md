# @huanlin/dsh-plugin-input-history · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 生成日期：2026-08-30。分析基线：插件 v0.2.0（工作区 `D:/Projects/deepseek-harness/dsh-plugin-input-history`），上游 tag `dsh-v0.1.2-alpha.1` (cd5ef81481) → `dsh-v0.1.2-alpha.2` (0a53fb55be)。所有上游结论均以只读 git 命令对照两个 tag 得出，未修改 `dsh/` 任何文件。

## 结论

**✅ 直接可升 —— 插件源码零改动。** 本插件消费的全部 dsh API 面（`conversation.composer.dock` slot 契约、`InputState.phase`、`inputActions.setDraft`、`useChat(s => s.legacy.nodes)`、`user`/`steering` 节点形状、三个 DOM 标记、locale/invariants 服务、`window.__ModuleLoader__` 加载契约）在 alpha.2 中逐项确认仍然存在且签名不变；上游本次破坏性点（`connectionGeneration`→`hostInfo` 注入 hook 改名）只落在 `ui-tool` / `ui-workspace` 的 slots 契约，本插件既不注入也不读取该 hook。peerDependencies `^0.1.2-alpha.1` 已语义化兼容 `0.1.2-alpha.2`，无需强制改版。

## 迁移步骤

**核心结论：`src/` 无需任何改动。** 需要做的只有「升级运行时 → 重建产物 → 重启验证」三件事。

### 1. 升级 dsh 源码 checkout（人类操作，按 DSH 源码 SOP）

1. 对 `~/.dsh/source/current`（Home 下 symlink）执行 `git pull --ff-only origin master` → `pnpm install --prefer-offline` → 前台长 timeout（≥600000ms）`pnpm run build`。alpha.2 后 HEAD 应为 `0a53fb55be` 或更高。
2. 产物抽查：`Test-Path "$src/apps/cli/lib/bin.js"`、`Test-Path "$src/packages/bundle/web-app/lib/index.js"`。
3. **禁止**在任何 dsh 目录跑写操作；本指南分析全程仅用 `git show/diff/grep/log` 只读命令。

### 2. 插件侧重建（无需改代码）

```powershell
Push-Location D:/Projects/deepseek-harness/dsh-plugin-input-history
pnpm run typecheck   # tsconfig paths/junction 现在解析到 alpha.2 的 lib/types —— 应零错误通过
```

- junction（`node_modules/@deepseek-ai/*` → `source/current/packages/*`）无需重建，指向内容随第 1 步自动变为 alpha.2。

## 升级后验证清单

以下全部在「dsh web 重启 + Ctrl+Shift+R 之后」执行：

1. **插件加载无报错**：页面不出现 `Failed to load plugins` / `missed the module table` / `Cannot find package '@deepseek-ai/…'` 提示——若出现，说明 dsh 源码升级后未完成 install/build（回到迁移步骤 1），而非本插件问题。
2. **dock 挂载**：DevTools Console 执行 `document.querySelector('[data-dsh-plugin-input-history]') !== null`，应返回 `true`（`display:none` 锚点在 composer 卡片下方）。
3. **与 StatsLine 同槽共存**：输入框下方 ui-chat 的统计行（slot id `stats`，order 0）仍正常渲染（alpha2 `ui-chat/src/client/apply.ts:152-154` 确认未迁走）。
4. **历史收集 + 回忆**：在任一会话发送一条新消息 → 点回输入框按 **↑**，应填入刚发送的这条 prompt；继续 **↑** 向更旧回溯。
5. **草稿恢复**：输入一段未发送文本 → **↑** 进入历史 → 连按 **↓** 越过最新条目，应恢复刚才那段在途草稿。
6. **持久化**：硬刷新浏览器后再按 **↑**，历史仍在（localStorage key `dsh-plugin-input-history:v1`）。
7. **多行边界**：输入多行草稿、光标置于中间行按 **↑/↓** 应正常移动光标（不劫持）；光标在第一行按 **↑**、最后一行按 **↓** 才触发历史导航。
8. **IME 安全**：切换中文输入法、候选词组合态按 **↑/↓** 应移动候选高亮（`isComposing`/keyCode 229 守卫未被上游变更破坏）。
9. **斜杠菜单仲裁**：输入 `/`（或 `@`）弹出触发菜单后按 **↑/↓** 应移动菜单高亮行（`[data-trigger-menu]` 标记检查生效）。
10. **提交事务门**：点击发送的瞬间（`phase` 进入 submitting）按方向键不应触发导航。
11. **会话切换**：A 会话导航到历史中途后切到 B 会话，光标/已存草稿应重置，不会把 A 的草稿写进 B。
12. **hero 休眠**：新建空白会话（hero 态）时 `[data-dsh-plugin-input-history]` 不存在；发出第一条消息会话激活后恢复。
13. **typecheck 门禁**：在插件目录跑 `pnpm run typecheck` 通过——这是「junction 类型已对准 alpha.2 且无 API 漂移」的静态证明。
